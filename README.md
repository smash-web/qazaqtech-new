# QazaqTech News

Портал мировых технологических новостей на казахском языке. Конвейер сам собирает новости из мировых изданий, отбирает 15–20 самых важных за день и пишет по ним оригинальные статьи на казахском со ссылками на первоисточники. Редакция управляет всем из админ-панели.

## Архитектура

```
 Мировые издания (RSS/Atom)
          │  каждые 20 мин
          ▼
 ┌──────────────── pipeline (Python) ────────────────┐
 │ 1. collect   сбор лент, дедупликация по URL       │
 │ 2. cluster   группировка публикаций в «сюжеты»    │
 │ 3. score     эвристика + оценка ИИ-редактора      │
 │ 4. select    отбор с учётом дневной квоты         │
 │ 5. write     статья на казахском (Claude)         │
 │ 6. QA        фактчекинг + глоссарий + корректура  │
 └───────────────────────┬───────────────────────────┘
                         │ REST API (ключ бота)
                         ▼
 ┌─────────── web (Next.js + Payload CMS) ───────────┐
 │ /admin       админ-панель редакции                │
 │ /            публичный сайт (SEO, RSS, sitemap)   │
 └───────────────────────┬───────────────────────────┘
                         ▼
                  PostgreSQL (cms + pipeline)
```

**Почему так:**
- Конвейер и сайт разделены. Конвейер может упасть, сломаться или масштабироваться отдельно, а сайт продолжит работать.
- Payload CMS даёт готовую админку с ролями, медиатекой и редактором. Работает внутри Next.js как одно приложение.
- Все редакционные настройки (квота, автопубликация, стилевой гайд, политика отбора, источники, глоссарий) хранятся в админке, а не в коде. Редактор меняет поведение ИИ без программиста.
- Статьи не переводятся дословно. ИИ пишет собственный текст по нескольким источникам и даёт ссылки на них. Это снижает юридические риски и лучше для SEO.

## Структура

```
pipeline/            Python-воркер
  qtnews/feeds.py      разбор RSS/Atom, извлечение текста
  qtnews/cluster.py    TF-IDF кластеризация сюжетов
  qtnews/scoring.py    оценка важности
  qtnews/selection.py  квота и равномерность в течение дня
  qtnews/writer.py     промпты: написание и проверка статьи
  qtnews/lexical.py    Markdown → формат редактора Payload
  qtnews/main.py       оркестрация и расписание
  tests/               тесты (pytest)
web/                 Next.js 15 + Payload CMS 3
  src/collections/     Статьи, Рубрики, Источники, Глоссарий, Медиа, Пользователи
  src/globals/         Настройки конвейера
  src/app/(site)/      публичный сайт
  src/app/(payload)/   админка и REST API
  src/seed.ts          начальные рубрики, 21 источник, глоссарий, бот
docker-compose.yml   прод: db + web + pipeline
```

## Локальный запуск (Windows / macOS / Linux)

Понадобятся: Node.js 20+, Python 3.12+, Docker Desktop.

```bash
# 1. База данных
docker compose -f docker-compose.dev.yml up -d

# 2. Сайт и админка
cd web
cp .env.example .env              # Windows: copy .env.example .env
npm install
npm run generate:importmap
npm run dev                        # http://localhost:3000/admin — создайте первого пользователя (станет админом)

# 3. Начальные данные (в новом терминале, из папки web)
npm run seed                       # выведет CMS_API_KEY для бота

# 4. Конвейер
cd ../pipeline
python -m venv .venv && .venv\Scripts\activate     # macOS/Linux: source .venv/bin/activate
pip install -r requirements-dev.txt
copy .env.example .env             # впишите CMS_API_KEY и ANTHROPIC_API_KEY
python -m qtnews.main collect      # собрать новости
python -m qtnews.main process      # отобрать и написать статьи
pytest                             # тесты
```

По умолчанию **автопубликация выключена**: статьи попадают в «Статьи» со статусом «На модерации». Редактор проверяет и публикует. Когда качество устроит, включите «Публиковать автоматически» в «Настройках конвейера». Тогда статьи, прошедшие ИИ-проверку без замечаний, будут выходить сами.

## Продакшен

1. VPS с Docker (например, 4 vCPU / 8 ГБ, хостинг в Казахстане или Европе), домен, reverse-proxy с HTTPS (Caddy или Nginx), перед ним Cloudflare.
2. `cp .env.example .env`, заполнить значения.
3. Перед первым деплоем создайте миграции схемы на dev-машине: `cd web && npm run payload migrate:create` и закоммитьте папку `src/migrations`.
4. `docker compose up -d --build`. Контейнер web сам применяет миграции при старте.
5. Создайте админа в `/admin`, затем выполните `docker compose exec web npm run seed` и впишите выданный `CMS_API_KEY` в `.env`. После этого `docker compose up -d pipeline`.
6. Бэкапы: ежедневный `pg_dump` баз `cms` и `pipeline` и тома `media` во внешнее хранилище.

## Как масштабировать дальше

| Когда | Что сделать |
|---|---|
| Медиа больше нескольких ГБ или несколько серверов | `@payloadcms/storage-s3` → Cloudflare R2 / S3 |
| Нагрузка на сайт | CDN-кэширование HTML в Cloudflare, несколько реплик `web` |
| Сотни источников | Вынести стадии конвейера в очередь (Redis + отдельные воркеры), эмбеддинги + pgvector вместо TF-IDF |
| Нужен поиск | Meilisearch / Typesense |
| Вторая версия сайта | Латиница (транслитерация на лету), русская/английская версии через поле `locale` |
| Дистрибуция | Автопостинг в Telegram-канал, push-уведомления, Google News sitemap |

## Важно

- **Источники.** Reuters и Bloomberg не отдают публичный RSS. Для них нужен лицензионный доступ. Список лент в `seed.ts` стоит проверить: если адрес изменился, источник пропускается с предупреждением в логе.
- **Изображения.** Фото из чужих статей не используем. Подходят стоки с лицензией, пресс-киты компаний или собственные иллюстрации. Поле «Автор / лицензия» у медиафайлов обязательно.
- **Юридическое.** Регистрацию сетевого издания по законодательству РК и правила маркировки ИИ-контента уточните у юриста.
